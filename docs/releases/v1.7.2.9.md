# Watch Together v1.7.2.9 测试版

本版修复服务器已经报告 Stop 后，插件先前捕获的旧快照仍可能继续参与同步的问题。

## 修复与兼容

- 兼容 Emby 在 Stop 通知前替换播放状态对象的行为，撤销该次播放已关联的历史快照，避免继续使用旧进度发送后续同步命令。
- 明确的新 Start 可以恢复新快照，不能重新激活旧快照；同一播放 ID 的新对象不受可识别的旧对象迟到 Stop 影响。
- 排队的暂停、继续、定位和换片命令在交给 Emby 前复查目标快照是否失效。
- 不修改 ETE 或客户端协议，不新增片尾阈值或等待下一条进度的确认延迟，正常拖动、连续快进及远控同步沿用现有流程。
- 沿用现有配置和房间格式，无需迁移。

## 验证与边界

- 已用实际插件实现和 SDK 夹具验证状态替换、命令间 Stop、Start 解锁、迟到事件、目标排队失效及正常同步回归；离线验证不等同于真实双客户端播放验收。
- Stop 前尚未观察到有效播放身份、同对象复用 ID 且事件乱序等情况仍可能无法可靠区分。停止 ID 没有有效新 Start 时仍保持停止。
- 主端在整组检查后停止、而目标端仍有效的部分排队窗口尚不能覆盖；已越过最终发送检查或交给 Emby 的命令不能撤回。
- Stop 之前到达的异常跳变仍可能同步；本版不声称解决首次 EOF 或所有播放失败。

本版为 beta/prerelease，正式通道保持原版本。安装后需要重启 Emby Server；请在确认可中断播放的窗口操作。
