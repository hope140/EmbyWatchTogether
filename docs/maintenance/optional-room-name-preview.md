# 可选房间名称预览

基线为 beta `a9d19896b39435a6582a182b7fd786bf80aff654`（公开产品基线 1.7.2.18）。本页保留预览调查；最终 name-preview3 用户确认后整理为 [1.7.2.19 测试版](../releases/v1.7.2.19.md)，不改变同步、权限、邀请有效期、单次使用或成员冲突规则。

- 手动创建和接受邀请创建房间时，空白名称由 `RoomManager` 统一生成。已有非空名称保留原语义；邀请名称仍在接受时成为房间名称。
- 在既有注册锁内，枚举“房间 #0000”到“房间 #9999”的空闲名称，随机选择其中一个，使用固定四位 ASCII 数字。每次分配最多检查 10,000 个编号，不依赖随机碰撞重试。检查名称、随机选择、写盘和注册处于同一临界区。比较现有名称时忽略两端空白；显式命名的同格式房间也会占用编号。
- 空名称邀请在接受前显示“接受邀请后生成房间名”，不提前分配编号；实际创建后才生成并持久化随机名称。此前预览的首个空号分配及邀请列表“未命名房间”兜底不符合需求，本轮修正；已创建的名称保持原样，不迁移或重新随机。
- 名称写入现有房间元数据，读取、刷新或重启不会重新生成。删除房间后编号可重用；旧空名称不迁移。用户手填重名仍按原规则允许，不把显示名称变成房间身份。
- 10,000 个编号全被占用时有界失败；不添加房间，不占用成员，不消耗邀请码。用户可填写自定义名称，或释放编号后重试；邀请失败仍使用现有 `room_unavailable` 状态，不新增协议。
- 复制失败显示“自动复制失败，请手动复制邀请码。”；兼容剪贴板缺失、同步抛错和异步拒绝，保留已生成的邀请码与有效期，不重新创建邀请。离页后旧回调不更新反馈。
- 页面、控制器和路由缓存身份一并更新至 V23；1.7.2.18 公开资产仍为 V21。

验证覆盖两条真实服务入口、混合并发、编号耗尽与邀请重试、持久化/重启、写盘失败、空白/显式名称、成员/权限保护、表单重置及复制失败隔离。浏览器 fixture 和后端自动测试不等于真实 NAS 故障注入或全客户端验收；部署后仅核验加载、资源、健康及原数据，用户再观察实际创建与复制。

Knowledge Review：名称分配必须与房间注册共享原子边界；邀请码创建时提前分配会造成接受时碰撞，故只在最终创建房间时分配。现有锁与持久化机制足够，无新 ADR 或数据格式迁移。
