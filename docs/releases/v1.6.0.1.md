# Watch Together v1.6.0.1

## 版本性质

- 本版本从 `beta` 分支发布为 GitHub prerelease，兼容基线为 stable `v1.5.0.0`。
- `v1.5.0.4` 的发布流程因 CI flaky test 在 Release 创建前中止，没有生成 GitHub Release 或发布资产；其 Git tag 保留且不复用。
- 本版本是 Phase D Media Handoff 的第一版正式 beta 测试包，不包含 Phase E。

## 新增功能

- Primary 在 `Watching` 中切换到下一集或其他 Item 时，Participant 自动请求打开相同 Item。
- PlayItem 成功发送后不会立即视为完成，必须等待 SessionSnapshot 确认当前 User、Session 和 ItemId。
- 确认双方进入同一 Item 后，复用现有 Barrier 对齐 Pause、Seek 和 Restore 时间轴。
- 支持自动连播 Stop → Start 的切集识别，避免先触发普通停止副作用。
- Participant 自己主动切到第三个 Item 时取消当前自动 Handoff，不会被继续强拉回去。
- Participant 可以通过 Resync 跨 Item 回到 Primary 当前媒体。
- Primary 连续 B → C 时旧 Handoff operation 会失效，迟到的旧 B 不得污染当前目标。
- Session identity 变化会使旧 operation generation 失效；PlayItem 具有超时和有限重试。

## 配置与兼容性

- 不修改房间持久化格式，不新增外部依赖。
- 不改变现有 Pause、Resume、Seek 基本语义，不启用周期性漂移 Seek。
- 继续只支持双人、同一服务器同步，不支持多人、跨服务器或播放列表同步。
- 不包含掉线恢复、换设备恢复、Session migration 或其他 Phase E 内容。

## Beta 验证重点

发布后仍需在真实客户端确认：

1. 自动播放下一集。
2. Primary 手动切换下一集。
3. Participant 客户端对 PlayItem 的兼容性。
4. Item 切换后的 SessionInfo 更新时间。
5. Handoff → Barrier 的实际时序。
6. Participant 主动切到第三个 Item。
7. 跨 Item Resync。
8. Primary 连续 A → B → C。
