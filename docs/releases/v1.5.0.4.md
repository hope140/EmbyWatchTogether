# Watch Together v1.5.0.4

## 版本性质

- 本版本从 `beta` 分支发布为 GitHub prerelease，基于 stable `v1.5.0.0`。
- 本版本包含此前 `v1.5.0.3` beta 中的更新通道、同步安全、会话选择、消息发送和邀请清理修复。
- 本版本新增 Phase D Media Handoff，用于继续进行真实 Emby 客户端验证。

## 新增功能

- `Watching` 中 Primary 切换到下一集或其他 Item 时，Participant 会自动请求打开相同 Item。
- PlayItem 发送成功后不会立即视为完成，必须等待当前 Participant 的 SessionSnapshot 确认 User、Session 和 ItemId。
- 双方确认进入相同 Item 后，继续复用现有 Barrier 对齐 Pause、Seek 和 Restore 时间轴。
- 识别自动连播中的 Stop → Start 切集过程，避免先触发普通停止副作用。
- Participant 在 Handoff 期间主动切到第三个 Item 时取消本次自动 Handoff，不会被继续强拉回去。
- Participant 可以通过 Resync 跨 Item 回到 Primary 当前媒体。
- Primary 连续从 B 切到 C 时，旧 B Handoff 会失效，迟到的 B 状态不能污染当前目标。
- Session identity 变化会使旧 operation generation 失效；PlayItem 具有超时和有限重试。

## 配置与兼容性

- 不修改房间持久化格式，不新增外部依赖。
- 不改变现有 Pause、Resume、Seek 基本语义，不启用周期性漂移 Seek。
- 继续只支持双人、同一服务器同步，不支持多人、跨服务器或播放列表同步。
- 本版本不包含 Phase E 的掉线恢复、换设备恢复或 Session migration。

## Beta 验证重点

发布后仍需在真实客户端确认：

1. 自动播放下一集。
2. Primary 手动切换下一集。
3. Participant 客户端对 PlayItem 的兼容性。
4. Item 切换后的 SessionInfo 更新时间。
5. Handoff → Barrier 的实际时序。
6. Participant 主动切到第三个 Item。
7. 跨 Item Resync。
8. Primary 连续 A → B → C。

## 测试状态

- 自动测试、Release 构建、路径防护、CI、签名和发布 workflow 静态检查在发布前执行。
- 本 beta 的自动验证不等于真实客户端验收；完成 Phase D 实机验证后再评估 `1.6.0.0` stable。
