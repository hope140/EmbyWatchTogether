# 客户端兼容性记录

## 2026-10-18 控件调整候选验收

当前方案保持本轮部署前服务器的单页布局，页面包含创建房间、邀请、房间、说明和设置等原区域；既有按钮、输入框、选择框和 checkbox 使用 Emby 原生控件样式。程序集版本暂保留 `1.6.0.5`，具体构建以部署记录的 SourceCommit、DLL SHA-256 和 `WatchTogetherSettingsV5` 页面键识别。

NAS 当前候选：源码 `55f101c`，2026-10-18 20:03（东八区）部署，DLL SHA-256 `fdc30f80…716f4674`。本地 .NET 545 项、UI 浏览器 35 项和构建门禁通过；真实 Web 只读验证了单页区域、静态/动态原生按钮、配置读取和 Token 状态。以下播放与真实手机项目尚待人工验收。

建议两名参与者使用不同账号，每个账号先只保留一个播放客户端。页面约每 5 秒刷新，操作后等一轮状态再判断。

今晚优先验证：

1. **界面和权限**：电脑、手机上页面区域和房间布局与原服务器版本一致；原生按钮、输入、选择和 checkbox 可用且不挤压；普通用户隐藏创建房间和管理员设置，仍能进入自己的房间。看到旧缓存时先强制刷新。
2. **基本同步**：双方打开同一视频，进入同步后分别暂停、继续及明显拖动进度，另一方应跟随；请求重新对齐后能回到同步，不反复跳动。
3. **换集重点**：主用户手动下一集和自然播完自动下一集各测一次，被控方应进入相同目标集，重点看是否仍发生多跳一集；不要连续点击或立即手动修正被控方，以免混淆记录。
4. **停止与重新进入**：主用户停止后，状态持续约 2 秒才确认，另一方按配置暂停/提示；重新打开同一视频可以继续同步。主用户新视频晚到仍使用 beta 的晚到换集识别。

补充验证：

- 邀请码重新创建、复制和接受；重启前的旧邀请码失效是预期。“暂离”保留成员关系，“结束”才解除房间。
- 管理员保存设置后重新进入仍保留；Token 只显示是否配置，不回显，不必为验收清除已有 Token。
- 连续观看 20–30 分钟，观察频繁暂停、跳进度或反复对齐。可选参与者短时断连恢复；原 Session/Item 才能继承 Recovery，实际状态以诊断为准。

异常回报请附东八区操作时间、双方客户端及版本、操作步骤、预期与实际、房间状态；优先使用插件导出的脱敏诊断 JSON 和截图，无需粘贴完整服务器日志或 Token。

## 已验证事实

- Emby Web `4.9.5.0` 可以从插件配置页的“Watch Together”入口打开本页。
- 使用已登录的管理员浏览器会话打开页面时，房间列表读取请求可以使用当前 Emby Web 登录态完成认证。
- 直接把诊断接口地址粘贴到浏览器地址栏不携带插件页面使用的认证请求头，因此不能用地址栏返回的 `401` 作为页面登录态验收结果。
- 2026-09-07 使用 NAS Basic4 上部署的 beta 诊断构建，在已登录管理员页面点击“查看诊断”成功显示脱敏状态、参与者会话、Pending、Barrier、恢复窗口、最近结果和事件记录。
- 同一页面成功导出诊断 JSON；文件可解析，包含 2 个会话和 1 条事件，未发现 Token、路径或原始 ID 字段。
- 2026-09-09 用户复测确认非管理员可以从 Emby 用户菜单进入 Watch Together 页面，页面显示参与者视角内容。
- 2026-09-09 用户确认 S4 参与者重新同步流程完成验收；该能力随后随 `v1.4.5.0` 纳入正式发布链，并由 `v1.5.0.0` 继续保留。
- 2026-09-12 用户反馈正式版发布后的昨夜连续播放未观察到明显的播放或同步异常。

## 运行观察边界

上述连续播放记录是用户口述的正向运行观察；本次未记录具体客户端、媒体样本、开始/结束时间、插件构建号或服务器日志。因此它可以支持继续进入阶段 D 的受控验证，但不能单独证明所有客户端兼容、自动下一集、任意换片或长时间运行的完整验收。

## S2/S3 诊断接口与页面

S2 的诊断 payload 通过当前房间页面的“查看诊断”入口读取，S3 页面负责展示和导出。管理员入口、脱敏内容和导出流程已在 Emby Web `4.9.5.0` 中验证；非管理员入口和 S4 参与者重新同步已由用户在测试环境复测确认。同步中 Barrier、Pending 控制和长时间播放仍应作为后续运行观察项目记录。
