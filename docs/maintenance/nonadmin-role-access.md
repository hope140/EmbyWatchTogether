# 非管理员页面角色读取修复

固定基线为 `1897aba7562995ee41a432739a1e1fc00c2565d4`。变更范围仅为页面初始化、浏览器夹具及回归测试；不改同步、播放、权限规则或布局。

2026-11-12 的 Emby 4.10.0.40 真实日志显示，普通用户请求 `WatchTogether/Users` 时，`WatchTogetherService.RequireAdmin()` 抛出 `UnauthorizedAccessException: administrator privileges required`，最终响应为 HTTP 500。前端原先通过这个管理员接口探测身份，将该响应按服务器故障显示。模拟 403 不能证明真实宿主映射。

服务器随附 `modules/emby-apiclient/apiclient.js` 的 `getCurrentUser(options)` 使用当前用户 ID 调用 `getUser(id, options.enableCache, options.signal)`。页面现在通过 `getCurrentUser({enableCache:false})` 读取当前身份，仅接受匹配用户 ID 和明确的布尔 `Policy.IsAdministrator`。普通用户直接进入自己的房间和邀请；只有管理员读取用户目录。角色读取失败保持可见错误，不默认管理员，不将全部 500 解释为权限拒绝。

角色请求复用现有页面请求及生命周期保护，账号、服务器或页面代次变化后旧结果不能授权或发起用户目录请求。服务端仍按当前身份过滤房间并执行全部权限检查；页面角色不是安全边界。

本次不规范化服务端异常为 403。固定 SDK 包不提供当前 Emby HTTP 服务器的完整异常映射实现，未以猜测异常类型替换公共行为。真实宿主已观察到的映射为 500；其他异常类型的 403 行为未验证。

验证范围包含管理员/普通用户、空房间和所属房间、角色失败/缺失/不匹配、迟到角色、邀请及真正 500 提示。服务端既有测试覆盖成员与暂离成员可见、他人房间不可见。浏览器模拟不替代实机验收，尚未部署本修复。

建议部署后分别用普通用户及管理员打开页面：普通用户仅有房间和邀请，不出现用户目录失败提示，网络中没有 `WatchTogether/Users`；管理员保持创建和设置。再确认普通用户仅能查看自己的房间且邀请可用。真实角色读取失败、权限变更和异步切换仍需按实际客户端验证。

Knowledge Review：权限异常在宿主中的 HTTP 映射必须用运行证据核实；不能把管理员接口失败作为普通用户角色的正常探测方式。本次无架构或 ADR 变更。
