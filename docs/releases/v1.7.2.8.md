# Watch Together v1.7.2.8 测试版

本版只收窄处理一种情况：服务器已收到某次播放的 Stop，随后旧进度迟到，不应再把它当作新的拖动同步给另一端。

## 修复与兼容

- 按服务器会话和播放 ID 记录停止，覆盖 Emby 删除旧播放对象后、迟到进度重新创建同 ID 对象的路径；发送 Seek、继续播放或换片前复查已选快照的停止标记。
- 正常拖动、连续快进、拖近片尾和暂停时拖动继续使用现有同步流程；没有新增等待下一条进度的确认延迟，也没有片尾位置阈值。
- 明确的新 Start 可以重新使用播放 ID；不同播放 ID、不同服务器会话不会继承旧停止标记。停止后的暂停和通知仍使用原有确认窗口。
- 不修改 ETE，不增加客户端协议依赖，不改变远控能力资格判断。保留 v1.7.2.7 已有功能和配置格式。

## 已知边界

- 错误位置先于 Stop 到达时仍可能同步；本版不声称解决最初的 EOF 或全部播放失败。
- 缺失或冲突的身份不作整台设备的推断，可能无法过滤旧报告。同 ID 重用且事件无法鉴别时，仍可能误同步或误过滤；同 ID 恢复却没有明确 Start 时会继续视为停止。
- 已越过发送检查的在途命令不能撤回。会话内停止记录随播放次数增长，服务器会话对象回收时释放。
- 自动化回归覆盖实际 SDK 和插件状态机，但不等于真实双客户端播放验收。

本版为 beta/prerelease，正式通道保持原版本。安装后需要重启 Emby Server；请在没有播放的窗口操作。
